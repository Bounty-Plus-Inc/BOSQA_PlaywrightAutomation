# Developer Tutorial

This guide is for adding new automation scenarios without having to rediscover the project shape every time.

The short version:

1. Put test flows in `tests/<area>/`.
2. Put reusable page actions in `tests/pages/`.
3. Add screenshots at meaningful checkpoints.
4. Register the scenario in `vite.config.js`.
5. Add a button/card in `src/App.jsx` when it should run from the dashboard.

## Folder Map

| Folder | What Goes Here |
| --- | --- |
| `tests/sales/` | Sales-related Playwright specs, like Sales Order and Delivery Order. |
| `tests/admin/` | Admin or approval-related Playwright specs. |
| `tests/pages/base/` | Shared page objects like `BasePage`, `LoginPage`, and `MainMenuPage`. |
| `tests/pages/transactions/` | Transaction pages like `SalesOrderPage` and `DeliveryOrderPage`. |
| `tests/pages/approvals/` | Approval pages like credit limit and transaction approval. |
| `tests/pages/popups/` | Popup helpers like business partner and item lookup windows. |
| `tests/helpers/` | Cross-test utilities for env loading, screenshots, and summaries. |
| `src/` | React dashboard UI. |
| `vite.config.js` | Vite config plus local API endpoints used by the dashboard. |

## Add A New Scenario

Start with the spec. A spec should read like a clean business flow.

Example:

```js
const { test } = require('@playwright/test');
const { LoginPage } = require('../pages/base/LoginPage');
const { MainMenuPage } = require('../pages/base/MainMenuPage');
const { takeStepScreenshot } = require('../helpers/screenshots');
const { finishRunSummary, recordModuleDocNo, startRunSummary } = require('../helpers/runSummary');

test('My New Scenario', async ({ page }) => {
  test.setTimeout(180000);

  const testId = 'my-new-scenario';
  const testName = 'my new scenario';
  const loginPage = new LoginPage(page);
  const menu = new MainMenuPage(page);

  startRunSummary(testId, 'My New Scenario');

  await loginPage.loginAs();
  await menu.openSalesOrder();
  await takeStepScreenshot(page, testName, '00_PAGE_OPENED');

  recordModuleDocNo('My Module', '', 'Opened', testId);
  finishRunSummary('success', testId);
});
```

Use a stable `testId`. It becomes the key for dashboard results and summary files.

## Add Page Actions

Keep selectors and repeated behavior inside page objects.

Good:

```js
await salesOrder.selectDocSeries('359');
await salesOrder.addItems({ itemCode, unitPrice: '100', businessCenter: 'NCRCL', count: 3 });
```

Avoid putting long selector chains directly in the spec unless it is a one-off checkpoint.

Use the existing page groups:

- Transaction page? Add it to `tests/pages/transactions/`.
- Popup? Add it to `tests/pages/popups/`.
- Approval flow? Add it to `tests/pages/approvals/`.
- Shared navigation/login/helper page? Add it to `tests/pages/base/`.

Most BPI screens use frames, so prefer `findInAllFrames()` from `BasePage`.

```js
const button = await this.findInAllFrames('a#btnAdd[name="btnAdd"]', 20);
await button.click();
```

## Add Screenshots

Screenshots make the dashboard and PDFs useful.

```js
await takeStepScreenshot(page, testName, '01_CUSTOMER_SELECTED');
```

Naming style:

- Start with a number for normal flow: `00_`, `01_`, `02_`
- Use clear names: `04_ITEM_UPDATED`
- Use `ZZ_` for failure or diagnostic captures

The folder name comes from `testName`, with spaces converted for the screenshot path.

## Add Result Metadata

Dashboard result ordering and descriptions live in `vite.config.js` inside `testResults`.

Add a new entry:

```js
'my-new-scenario': {
  title: 'My New Scenario',
  screenshotsDir: 'test-results/screenshots/my_new_scenario',
  steps: {
    '00_PAGE_OPENED.png': {
      title: 'Page opened',
      description: 'The scenario reached the target page.'
    }
  }
}
```

Then register the spec in `testSpecs`:

```js
const testSpecs = {
  'tests/sales/standard.spec.js': 'sales-standard',
  'tests/sales/my-new-scenario.spec.js': 'my-new-scenario'
};
```

## Add It To The Dashboard

Open `src/App.jsx`.

For a sales scenario, add to `salesTests`:

```js
{
  id: 'my-new-scenario',
  label: 'My New Scenario',
  spec: 'tests/sales/my-new-scenario.spec.js',
  resultId: 'my-new-scenario'
}
```

For an add-on/admin scenario, add to `addOnTests`.

That is enough for the animated Sales/Adds-On buttons to show the new scenario.

## Add Environment Values

Use environment variables for data that changes by environment or user.

In the spec:

```js
const itemCode = process.env.BPI_SALES_ITEMCODE || '10000002';
```

In `.env.example`, document the variable:

```txt
BPI_SALES_ITEMCODE=10000002
```

The project loads `.env` and `.env.local` from `tests/helpers/env.js`.

## Repeat Items

Sales Order supports repeated item entry.

From the dashboard, set the `Items` input before running `SO with Credit Limit`.

From CLI or PowerShell:

```powershell
$env:BPI_SALES_ITEM_COUNT = "3"
npx playwright test tests/sales/standard.spec.js --headed
```

The test clamps the count from `1` to `20`.

## Run And Check

Useful commands:

```bash

npx playwright test tests/sales/standard.spec.js --headed
npm run playwright-report
```

Quick syntax checks:

```bash
node --check tests/sales/my-new-scenario.spec.js
node --check tests/pages/transactions/MyPage.js
```

## A Friendly Pattern For New Work

When adding a scenario, move in this order:

1. Make the page object action you wish already existed.
2. Write the spec using that action.
3. Add screenshots at the business milestones.
4. Register results in `vite.config.js`.
5. Add the dashboard entry.
6. Run one focused spec before running everything.

Keep specs readable. A future teammate should be able to scan the test and understand the business process without parsing every selector.

## Common Tips

- Prefer waits for real UI state, not fixed sleeps.
- Keep popups in `tests/pages/popups/`.
- Keep transaction form logic in `tests/pages/transactions/`.
- Keep approval-specific logic in `tests/pages/approvals/`.
- Use `recordModuleDocNo()` when a scenario creates or approves a document.
- Use `readCurrentDocNo(pageOrPageObject)` or `recordCurrentDocNo(moduleName, pageOrPageObject, status, testId)` from `tests/helpers/docNoReader.js` when a module has a standard `df_docno` field.
- Keep screenshot names stable because `vite.config.js` depends on them.
- If the dashboard can run it, the spec must be registered in both `testSpecs` and the correct array in `src/App.jsx`.
